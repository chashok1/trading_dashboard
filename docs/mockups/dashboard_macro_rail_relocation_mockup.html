Mockup v3 — Sectors' real two-row-per-sector anatomy fixed, panels bin-packed to minimize white space. Two fixes from your last round of feedback:
  • Sectors was missing rows. Its real markup (web/macro_areas.js::renderSectorsPanel/ etfProxyRowHtml) is TWO rows per sector, not one: a stance row (Long/Short arrow + full-width name + Td/Tn + range bar) plus an indented ETF-proxy sub-row (the sector's representative ETF, plain price+%chg text, own Td/Tn/range bar) — 11 sectors × 2 rows + 2 summary lines (Laggards/Rotate in) = 24 row-equivalents, not 11. That makes Sectors the tallest panel now, not a small one — fixed below with its real anatomy.
  • No more fixed 4-across grid. A rigid grid wasted space under every short panel sharing a row with a tall one (e.g. Credit's 2 rows next to Sectors' 24). The script below now measures every panel's real rendered height, then bin-packs them into columns with a largest-first greedy algorithm (small panels stack together to fill a column, matching a tall panel next to them) — it tries 3/4/5 columns and keeps whichever leaves the least empty space at the bottom of any column. The measured result prints live under the layout below.
  • Row content itself is unchanged from v2: real .msr-row/.msr-data-cluster/ .msr-rb/.msr-chg classes and values, copied from web/styles.css.
  • Right rail still keeps Volatility / Major Markets / Correlation / Symbol / Indicator only.

Open questions before I build this for real

  • Sectors' ETF sub-row is now approximated. I dropped the candle from it (the real etfProxyRowHtml doesn't draw one either — confirmed in the source) but the price column shows a placeholder number, not a real one (this mockup has no live price feed). That's fine for a layout mockup but flagging so you're not comparing exact digits.
  • Column order is now height-driven, not name-driven. The bin-packer sorts panels largest-first and drops each into whichever column is currently shortest — so which panels land in which column (and their top-to-bottom order within a column) is whatever balances best, not the Sectors→Country-ETFs reading order from today's right rail. Is that OK (packing efficiency wins), or do you need the reading order preserved even if it leaves more white space?
  • Column width — fixed at 270px per column (matching today's right-rail panel width) so row content doesn't need to change size. Check the live "N columns... tallest column NNNpx" callout below once you open the file — if the packer picks 5 columns, that's 5×270px+gaps ≈ 1400px of middle-column width; let me know if that's wider than your actual window so I can bias it toward fewer/wider columns instead.
